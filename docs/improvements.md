# План доработок

Приоритет: P0 — до промышленного использования, P1 — ближайшие итерации,
P2 — по мере необходимости.

## Уже реализовано

- 67 модульных тестов ключевых правил и формы результата.
- Подготовлен `ci/verify.yml` для GitHub Actions: три прогона, сверка эталона,
  идентичность SHA-256 и автоматическое определение ролей файлов.
- Контроль инициалов при сопоставлении коротких имён; неоднозначная фамилия
  больше не привязывается к произвольному сотруднику.
- Доступны только явно работающие сотрудники; больничный, командировка и
  прочие неизвестные статусы исключаются.

## Правила и данные

| Приоритет | Доработка | Зачем |
|---|---|---|
| P0 | Получить ответы на 10 вопросов (`docs/questions.md`) и заменить допущения на согласованные правила | Сейчас часть правил — допущения |
| P0 | Прогнать на реальных (обезличенных) данных заказчика и сверить с решениями сотрудников | Условие приёмки проекта |
| P1 | Вынести правила из кода в конфиг в `references/` (JSON/YAML): регионы Китая, словарь должностей, веса загрузки | Настройка без правки скрипта |
| P1 | Учитывать возраст заказов и cut-off в загрузке | Не перегружать логистов «горящими» заказами |
| P1 | Разрешение однофамильцев в группе через табельный номер | Сейчас неоднозначное имя безопасно пропускается; ID позволит учитывать такую историю |
| P2 | Поддержка .xls через xlrd для старых выгрузок | Разрешено заданием, сейчас только .xlsx |
| P2 | Ведение журнала прогонов рядом с входными файлами | Аудит распределений |
