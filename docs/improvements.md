# План доработок

Приоритет: P0 — до промышленного использования, P1 — ближайшие итерации,
P2 — по мере необходимости.

## Правила и данные

| Приоритет | Доработка | Зачем |
|---|---|---|
| P0 | Получить ответы на 10 вопросов (`docs/questions.md`) и заменить допущения на согласованные правила | Сейчас часть правил — допущения |
| P0 | Прогнать на реальных (обезличенных) данных заказчика и сверить с решениями сотрудников | Условие приёмки проекта |
| P1 | Вынести правила из кода в конфиг в `references/` (JSON/YAML): регионы Китая, словарь должностей, веса загрузки | Настройка без правки скрипта |
| P1 | Учитывать возраст заказов и cut-off в загрузке | Не перегружать логистов «горящими» заказами |
| P1 | Разрешение однофамильцев в группе через табельный номер | Точность сопоставления имён |
| P2 | Поддержка .xls через xlrd для старых выгрузок | Разрешено заданием, сейчас только .xlsx |
| P2 | Ведение журнала прогонов рядом с входными файлами | Аудит распределений |

## Инженерия

| Приоритет | Доработка | Зачем |
|---|---|---|
| P1 | Юнит-тесты (pytest) на чистые функции: `norm`, `group_of`, `extract_order`, `cloud_name_matches`, `match_headers` | Сейчас проверка только end-to-end на эталоне |
| P1 | CI (GitHub Actions): генерация данных → 3 прогона → сверка с эталоном → проверка идентичности SHA-256 | Регрессии при правках правил ловить автоматически |
| P1 | Расширить эталон: ФУЛ позже последней записи Cloud без заказа (граница пропусков), пересекающиеся поставщики между пачками, однофамильцы | Покрытие граничных случаев |
| P2 | Типизация и линтер (ruff/mypy), pre-commit | Единый стиль при командной разработке |
| P2 | Валидация результата перед сохранением: 12 колонок, нет пустых обязательных полей кроме «не определено» | Защита от ошибок при будущих правках |

## Продукт

| Приоритет | Доработка | Зачем |
|---|---|---|
| P1 | Замер экономии времени сотрудника на пачке (AS IS vs TO BE) | Целевая метрика проекта согласуется с заказчиком |
| P2 | Второй агент того же контура: подтверждение отклонений ФУЛ (сверка с заказом, черновик письма менеджеру бренда) | Наработки переносятся напрямую |
| P2 | Экспорт «Требует внимания» отдельным файлом для руководителя | Удобство разбора спорных заказов |
