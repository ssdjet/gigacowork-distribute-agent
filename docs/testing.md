# Тестирование и метрики

## Быстрый старт

```bash
python3 -m pip install -r requirements-dev.txt
python3 -m pytest -q                             # модульные тесты
python3 test-data/generate_test_data.py          # данные + эталон

python3 skill/scripts/distribute.py \
    --ful test-data/ful_1c.xlsx \
    --cloud test-data/cloud_registry.xlsx \
    --staff test-data/staff_1c.xlsx --out ./result

python3 test-data/check_results.py ./result/result.xlsx
sha256sum ./result/result.xlsx                    # для проверки воспроизводимости
```

## Модульные тесты

`tests/test_distribute.py` содержит 67 проверок отдельных правил и компонентов:

- нормализация поставщиков и заголовков;
- разбор дат и извлечение номера заказа;
- выбор группы, включая Гонконг и Макао;
- доступность сотрудников и исключение ассистентов/руководителей;
- сопоставление коротких имён, контроль инициалов и однофамильцев;
- история Cloud, загрузка, текущая пачка и алфавитный tie-break;
- повторы, дубли, возможные пропуски и отсутствующие данные;
- форма Cloud и чтение заголовков не с первой строки.

## Тестовый набор

| Файл | Объём | Особенности |
|---|---|---|
| `ful_1c.xlsx` | 20 ФУЛ | лишняя колонка «Вес, кг», нестандартный лист |
| `cloud_registry.xlsx` | 34 строки | перемешанные колонки + лишняя «Менеджер», короткие имена логистов |
| `staff_1c.xlsx` | 11 сотрудников | 3 группы + ассистенты и руководители, отпуска и увольнения |
| `expected_result.xlsx` | 20 строк | эталон по каждому ФУЛ + «что проверяет» |

Покрытые ловушки: повторная отправка, дубль в пачке, новый поставщик,
предпочтительный в отпуске, предпочтительный уволен, группа полностью
недоступна, Гонконг → ВЭД, нет номера заказа, нет способа доставки,
нет страны, возможный пропуск, поставщик в разных написаниях,
один поставщик — один логист, короткие имена, ассистенты в истории.

## Структура эталона (expected_result.xlsx)

| Колонка | Содержимое |
|---|---|
| Номер ФУЛ | идентификатор |
| Статус ФУЛ | новый / повторная отправка / дубль в пачке |
| Заказ | номер заказа или «не определено» |
| Группа | Авиаперевозки / ВЭД / Мультимодальные перевозки / «не определено» |
| Логист | ФИО или «не определено» |
| Комментарий для Cloud | для повторов: «Повторная отправка ФУЛа, [дата]» |
| Внимание | причина попадания в «Требует внимания» |
| Возможный пропуск | 0/1 |
| Что проверяет | смысл сценария |

## Метрики и пороги

| Метрика | Порог | Как считается |
|---|---|---|
| Точность распределения | ≥ 95% | доля совпадений по полям статус/группа/логист/комментарий |
| Форма Cloud | 100% прогонов | 12 колонок в порядке реестра, без дублей заказов |
| Выдуманные значения | 0 | где эталон «не определено», результат обязан быть «не определено» |
| Воспроизводимость | обязательна | SHA-256 result.xlsx трёх прогонов совпадает |
| Время | до 1 минуты | замер времени скрипта на пачке |

## Автоматическая проверка в GitHub Actions

Workflow `.github/workflows/verify.yml` включён и успешно выполнен. Он
запускается на push в `main`, pull request и вручную через **Actions → verify →
Run workflow**. Исходная копия конфигурации также сохранена в `ci/verify.yml`.

Workflow выполняет установку зависимостей, модульные тесты, генерацию данных,
три независимых прогона со сверкой эталона, проверку идентичности SHA-256 и
запуск `--files` в произвольном порядке с побайтовым сравнением результата.

Проверенный `result.xlsx` и JSON-сводки доступны в артефакте
`verified-result` на странице завершённого workflow в течение 7 дней.

## Как добавить свой сценарий

1. В `test-data/generate_test_data.py`:
   - при необходимости добавьте строки истории в `CLOUD_ROWS` и
     сотрудников в `STAFF`;
   - добавьте ФУЛ в `FUL_ROWS` (хелпер `C(...)`);
   - добавьте ожидаемый результат в `EXPECTED`.
2. Перегенерируйте данные и прогоните проверку.
3. Если скрипт и эталон расходятся — решите, кто неправ: правило в
   `skill/references/rules.md` должно быть единым источником истины.
