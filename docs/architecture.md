# Архитектура агента

## Принцип: решения принимает скрипт, модель — интерфейс

```
Пользователь (3 файла, сообщение может быть пустым)
        │
        ▼
Модель (GigaChat / любая) ── системный промпт + SKILL.md
        │  1. определяет, что это сценарий распределения
        │  2. запускает скрипт с путями к файлам
        ▼
distribute.py (детерминированный, Python 3 + openpyxl)
        │  читает Excel, применяет правила, принимает ВСЕ решения
        ▼
result.xlsx + JSON-сводка в stdout
        │
        ▼
Модель: прикрепляет файл, отвечает по шаблону,
объясняет решения по «Журналу решений»
```

Такое разделение — требование задания и инженерное решение одновременно:
- **Детерминизм.** На одних файлах результат всегда одинаков — метрика
  воспроизводимости выполняется по построению.
- **Проверяемость.** Правила тестируются без модели, на эталоне.
- **Нет галлюцинаций.** Модель физически не может назначить логиста или
  подставить значение: все значения формирует скрипт, а «не определено»
  ставится там, где данных нет.

## Компоненты

| Компонент | Роль |
|---|---|
| `system_prompt.txt` | роль агента, сценарий запуска, запреты |
| `skill/SKILL.md` | когда применять навык, команда запуска, шаблон ответа |
| `skill/scripts/distribute.py` | вся бизнес-логика, ~600 строк |
| `skill/references/rules.md` | правила и допущения человеческим языком |
| `test-data/generate_test_data.py` | синтетический набор с ловушками + эталон |
| `test-data/check_results.py` | сверка результата с эталоном, метрики |

## Устойчивость к формату входных файлов

- `match_headers()` — сопоставление заголовков по нормализованным
  синонимам (регистр, пробелы, кавычки, подстроки); каждая колонка
  используется один раз.
- `read_table()` — ищет лист и строку заголовков в первых 15 строках;
  требуется минимум совпавших колонок (ФУЛ 5, Cloud 8, сотрудники 3).
- `detect_role()` — при передаче файлов без ролей определяет тип каждого
  файла по набору найденных заголовков.
- Даты: Excel-даты и строки `ДД.ММ.ГГГГ`, `ГГГГ-ММ-ДД`, `ДД/ММ/ГГГГ`.

## Алгоритм (кратко)

Полное описание — `skill/references/rules.md` и раздел 3 PDF-отчёта.

1. Из комментария ФУЛ извлекается номер заказа (шаблон `S\d+`).
2. Заказ есть в Cloud → повторная отправка; уже был в пачке → дубль.
   В обоих случаях строка не создаётся.
3. Группа: air → Авиаперевозки; не air + Китай (вкл. Гонконг, Макао) → ВЭД;
   не air + не Китай → Мультимодальные. Нет данных → «не определено».
4. Кандидаты: «Работает», должность специалиста группы, без ассистентов
   и руководителей. Нет кандидатов → без логиста, в другую группу нельзя.
5. Логист: лидер истории Cloud по поставщику; если недоступен — следующий
   по истории; иначе наименее загруженный («в работе» + текущая пачка,
   tie — по алфавиту ФИО).
6. Один поставщик в пачке — один логист (сравнение названий без регистра,
   кавычек и пробелов).

## Воспроизводимость «байт-в-байт»

`result.xlsx` — zip-архив. Чтобы SHA-256 совпадал между прогонами:
- метаданные документа (`created`, `creator`) фиксированы;
- `dcterms:modified` в `docProps/core.xml` перезаписывается фиксированным
  значением (openpyxl проставляет текущее время при сохранении);
- метки времени всех zip-записей фиксированы при перезаписи архива.

Без этих мер хэш файла меняется от запуска к запуску даже при идентичном
содержимом.
