# Использование агента

## Основной сценарий

1. Выберите агента в GigaCowork.
2. Приложите три файла Excel (порядок не важен):
   - выгрузку ФУЛ из 1С;
   - реестр Cloud;
   - список сотрудников из 1С.
3. Отправьте сообщение — текст не нужен. Агент сам определит роли файлов
   по заголовкам, запустит скрипт и вернёт `result.xlsx`.
4. Перенесите строки из листа «Новые строки Cloud» в реестр вручную.
   Агент ничего не записывает в Cloud или 1С.

Ответ агента в чате — по шаблону:

> Готово. Новых строк Cloud: N. Повторных отправок: M (дублей внутри
> пачки: K). Возможных пропусков: P. Требует внимания: Q — см. лист
> «Требует внимания». Без логиста: R.

## Входные файлы

Общее: формат `.xlsx`, колонки находятся **по заголовкам**, а не по номеру.
Допустимы: другой порядок колонок, лишние колонки, любые названия листов,
заголовок не на первой строке (ищется в первых 15 строках).

### Выгрузка ФУЛ из 1С (по строке на ФУЛ)

| Колонка | Назначение |
|---|---|
| Дата | дата и время ФУЛ |
| Cutoff date | контрольная дата, переносится в Cloud как есть |
| Номер | номер упаковочного листа |
| Статус | статус ФУЛ (на распределение не влияет) |
| Комментарий | содержит номер заказа: «Номер:S0001234 от ДД.ММ.ГГГГ» |
| Способ доставки | air, sea, truck, direct truck, railway |
| Бизнес единица | бренд |
| Контрагент | поставщик |
| Страна | страна отправления |

### Реестр Cloud (история, 12 колонок)

Заказ, Поставщик, Бренд, Логист, Статус («в работе»/«confirm»),
Дата подтверждения, Cut-off, Дата получения УЛ, Страна отправления,
Способ доставки, Документы получены, Комментарий.

Имена в колонке «Логист» могут быть короткими («Жуков», «Иванов И.И.») —
сопоставляются с ФИО из 1С по фамилии и инициалам.

### Сотрудники из 1С

Наименование (ФИО), Текущее состояние («Работает», виды отпусков,
«Уволен»), Должность, Код (таб. №). Ассистенты и руководители групп
в распределении не участвуют.

## Результат: result.xlsx

| Лист | Содержимое |
|---|---|
| Новые строки Cloud | 12 колонок строго в порядке реестра; только новые заказы, без повторов и дублей |
| Повторные отправки | заказы, уже есть в Cloud, и дубли внутри пачки; готовый комментарий «Повторная отправка ФУЛа, [дата]» |
| Возможные пропуски | ФУЛ раньше последней записи Cloud, заказа в реестре нет — проверить вручную |
| Требует внимания | проблема по каждому спорному ФУЛ и что сделал агент |
| Журнал решений | статус, группа, логист и **основание решения** по каждому ФУЛ |

Поля новой строки Cloud: Статус = «в работе»; Дата подтверждения и
Документы получены = «не определено» (заполняет человек); Дата получения
УЛ = дата ФУЛ; остальное — из ФУЛ. Где данных нет — строго
«не определено», без подстановок.

## Частые вопросы

**Почему заказ отдан именно этому логисту?**
Откройте «Журнал решений»: там основание — история работы с поставщиком,
кто из предпочтительных недоступен и почему, либо расчёт по наименьшей
загрузке.

**Почему заказ остался без логиста?**
В его группе нет доступных специалистов (отпуска, увольнения) либо группа
не определена из-за отсутствия способа доставки/страны. В другую группу
заказ не передаётся — это правило заказчика.

**Что делать с «Возможными пропусками»?**
Это ФУЛ, пришедшие раньше последней записи Cloud, но отсутствующие в
реестре. Строка для них создаётся как обычно; решение о внесении — за
сотрудником.

## Ограничения (вне MVP)

- Запись в Cloud и 1С, коннекторы, уведомления логистам.
- Передача заказа в другую группу при недоступности своей.
- Изменение правил без согласования с заказчиком.
- Формат .xls (старые выгрузки) не поддерживается.
